# Disconfirmation report

**Result: all five candidate shortcut claims were rejected.** The playbook therefore requires effective-scope review and operational evidence in addition to configuration data. Eight synthetic edge cases produced the intended non-Pass classifications. These are documentary and artifact checks, **not empirical validation of a live Microsoft 365 tenant**.

The claim-level kill criteria were recorded in [research-preregistration.md](../research-preregistration.md) before the targeted falsification pass. The candidate claims were hypotheses to challenge, not beliefs attributed to the user. Search terms used in the automated documentary recheck were selected after reading the sources; they are a reproducibility aid, not an independent blinded experiment.

## Smallest falsifying checks performed

1. **Documentary review and recheck.** Read supporting and contradicting primary documentation. Fetch the source pages again and match the selected counterexample terms. Result: **5/5 candidate shortcuts met their claim-level rejection criterion**. The machine check located 11 of 11 selected indicators. Raw source text was not republished; the report records URL, final URL, response status, byte count and SHA-256. [Machine-readable source checks](source-checks.json).
2. **Eight synthetic evidence cases.** Apply the playbook's decision rules to explicitly constructed edge cases. Preregistered acceptance: **8/8** cases avoid unsupported Pass and match the intended result. Actual: **8/8**. [Machine-readable validation](validation-results.json).
3. **Artifact integrity.** Check every control's fields, unique IDs, registered citations, Microsoft-source coverage, local links and the initial Not assessed status of assessment rows. The final error count is recorded in the validation JSON. This checks document structure, not the truth of every recommendation.
4. **Reference accessibility.** All **88/88** registered source URLs returned HTTP 200 in the authoring check. HTTP success establishes availability at that time; it is not proof that every page's contents will remain unchanged or that every recommendation is universally applicable.
5. **Collection example syntax.** All five PowerShell snippets parsed with zero syntax errors. Local Microsoft.Graph.Authentication 2.39.0 metadata also confirmed the explicit HashTable output option. No snippet commands were run against a tenant. [Syntax-check record](powershell-parse-results.json).

These are intentionally small checks. The synthetic decision function encodes the published taxonomy, so agreement is a consistency check rather than independent evidence that the taxonomy is universally correct. The source review supplies the external counterexamples. Live tenant tests remain in the [fieldwork runbooks](../docs/FIELDWORK-RUNBOOKS.md).

## Specific advice corrected by current documentation

- **Emergency accounts:** do not publish a generic password-only MFA-bypass recipe. Use current independent strong-authentication, exclusion, monitoring and validation guidance. [S07: Manage emergency access accounts](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/security-emergency-access)
- **SMTP retirement:** the January 2026 Exchange Team notice replaces older 2026 removal dates. The current notice described unchanged behavior through December 2026, later default changes and a future final-removal announcement. Recheck it at execution; do not assume Basic SMTP has already disappeared. [S26: Updated SMTP AUTH Basic Authentication deprecation timeline](https://techcommunity.microsoft.com/blog/exchange/updated-exchange-online-smtp-auth-basic-authentication-deprecation-timeline/4489835)
- **Audit defaults:** enterprise defaults cannot safely be generalized to every Business subscription or trial. Verify ingestion in the correct Exchange Online session. [S60: Turn auditing on or off](https://learn.microsoft.com/en-us/purview/audit-log-enable-disable)
- **External forwarding:** “Automatic” is not treated as a universally equivalent explicit block. Inspect effective behavior and set a deliberate approved state when remediating. [S25: Control external email forwarding](https://learn.microsoft.com/en-us/defender-office-365/outbound-spam-policies-external-email-forwarding)
- **Copilot discovery controls:** restricted discovery does not repair permissions; older Restricted SharePoint Search has retirement guidance. Test direct access and follow current control availability. [S28: Restrict discovery of SharePoint sites and content](https://learn.microsoft.com/en-us/sharepoint/restricted-content-discovery); [S48: Restricted SharePoint Search](https://learn.microsoft.com/en-us/sharepoint/restricted-sharepoint-search)
- **Power Platform:** classic nonblockable-connector limitations should not be presented as the only possible policy model when advanced connector policies exist. Validate the model and enforcement modes in the tenant. [S75: Power Platform connector classification](https://learn.microsoft.com/en-us/power-platform/admin/dlp-connector-classification); [S50: Power Platform advanced connector policies](https://learn.microsoft.com/en-us/power-platform/admin/advanced-connector-policies)
- **eDiscovery:** use the current experience where applicable; the legacy documentation contains a specific 21Vianet exception. [S73: Purview eDiscovery legacy solutions](https://learn.microsoft.com/en-us/purview/ediscovery); [S39: eDiscovery features and components](https://learn.microsoft.com/en-us/purview/edisc-features-components)
- **Tool versions:** Maester's October 2026 preview transition includes breaking changes. Pin versions and review skips/errors rather than assuming every release has identical prerequisites. [S71: Maester 3.0 preview transition](https://maester.dev/blog/maester-3-0/); [S58: Maester installation guide](https://maester.dev/docs/installation/)

## Residual limitations

No real tenant data, licensed enterprise benchmark PDF, customer agreement, regulatory interpretation, operating-period sample or restore result was supplied. The public CIS catalog was reviewed, not the complete benchmark. Source pages and product rollouts can change after the research date. [S05: CIS Microsoft 365 Benchmarks](https://www.cisecurity.org/benchmark/microsoft_365); [S45: Microsoft Product Terms](https://www.microsoft.com/licensing/terms/); [S46: Office 365 GCC High and DoD](https://learn.microsoft.com/en-us/office365/servicedescriptions/office-365-platform-service-description/office-365-us-government/gcc-high-and-dod)

The test scripts validate source reachability, selected documentary counterexamples and artifact consistency. They do not validate cloud integrations, PowerShell runtime behavior against Microsoft 365, actual feature licensing, application safety, compliance certification or the effectiveness of the audit in every organization. The collection snippets are clearly labeled reference examples.
